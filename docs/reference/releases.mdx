title: Release files and verification

Download Zeabur Identity from [GitHub Releases](https://github.com/zeabur-oss/identity/releases), and verify signatures and checksums before running it. All Zeabur Identity releases during the alpha stage are marked as prereleases.

## Files and platforms

| Platform | CLI archive | Container image |
|---|---|---|
| Linux amd64 / x86_64 | `zeabur-identityctl-v<VERSION>-linux-amd64.tar.gz` | `ghcr.io/zeabur-oss/identity:<VERSION>` |
| Linux arm64 / aarch64 | `zeabur-identityctl-v<VERSION>-linux-arm64.tar.gz` | Use the same image tag; Docker selects your architecture |

For macOS, Windows, or other architectures, build the CLI from source.

Each release includes checksums, signatures, and SBOMs. An SBOM lists the dependencies included in a release file. Downloadable SBOM filenames end in `.cdx.json`.

## Image digests

The release file `digests.txt` lists the container image by digest: one line for each platform image and one for the multi-platform index. Pin a deployment to the `index` digest.

```text
linux/amd64  ghcr.io/zeabur-oss/identity@sha256:...
linux/arm64  ghcr.io/zeabur-oss/identity@sha256:...
index  ghcr.io/zeabur-oss/identity@sha256:...
```

`SHA256SUMS` covers `digests.txt` and every other release file, and `SHA256SUMS.sigstore.json` is its signature. The steps below verify both before reading a digest.

## Download and verify

Releases are signed in GitHub Actions by the shared release workflow of [zeabur-oss/.github](https://github.com/zeabur-oss/.github), which this repository's release workflow calls. The signing certificate therefore names `zeabur-oss/.github/.github/workflows/release.yml` as its identity, and `zeabur-oss/identity` with the release tag as the repository and ref it ran for. The commands below check all three.

You need the GitHub CLI (`gh`), `cosign` `3.x`, and GNU `sha256sum`. You also need Docker to pull images. Except for Docker, these command-line tools are available in the repository's `nix develop` shell.

<Steps>

<Step>

### Choose a version and architecture, and download the files

Set the release version and architecture, then download the files for that version:

```sh
version=v0.1.1
arch=arm64 # use amd64 for x86_64
identity='^https://github\.com/zeabur-oss/\.github/\.github/workflows/release\.yml@'
gh release download "$version" --repo zeabur-oss/identity --dir downloaded
```

</Step>

<Step>

### Verify the signature and checksums

Verify the signature on `SHA256SUMS` first, then use it to check the downloaded files.

```sh
(
  set -e
  cd downloaded
  cosign verify-blob --bundle SHA256SUMS.sigstore.json \
    --certificate-identity-regexp "$identity" \
    --certificate-github-workflow-repository zeabur-oss/identity \
    --certificate-github-workflow-ref "refs/tags/$version" \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
  sha256sum --check --strict SHA256SUMS
)
```

</Step>

<Step>

### Extract and run the CLI

After both checks pass, extract the archive and try the CLI:

```sh
tar -xzf "downloaded/zeabur-identityctl-$version-linux-$arch.tar.gz"
./zeabur-identityctl --help
```

</Step>

<Step>

### Verify and pull the container image

Read the image digest from the verified `digests.txt` file.

```sh
image=$(awk '$1 == "index" {print $2}' downloaded/digests.txt)
cosign verify --certificate-identity-regexp "$identity" \
  --certificate-github-workflow-repository zeabur-oss/identity \
  --certificate-github-workflow-ref "refs/tags/$version" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com "$image"
cosign verify-attestation --type cyclonedx --certificate-identity-regexp "$identity" \
  --certificate-github-workflow-repository zeabur-oss/identity \
  --certificate-github-workflow-ref "refs/tags/$version" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com "$image"
docker pull --platform "linux/$arch" "$image"
```

</Step>

<Step>

### Verify build provenance (optional)

GitHub also records build provenance for every release file and image. With an authenticated `gh`:

```sh
gh attestation verify "downloaded/zeabur-identityctl-$version-linux-$arch.tar.gz" \
  --repo zeabur-oss/identity --source-ref "refs/tags/$version" \
  --signer-workflow zeabur-oss/.github/.github/workflows/release.yml
gh attestation verify "oci://$image" \
  --repo zeabur-oss/identity --source-ref "refs/tags/$version" \
  --signer-workflow zeabur-oss/.github/.github/workflows/release.yml
```

</Step>

</Steps>
