設定 Google OAuth 用戶端，再把 Google 帳號連結到 Zeabur Identity 使用者。使用者就能在登入頁選擇 **Continue with Google**。管理員帳號只能用通行密鑰登入，不能連結 Google 帳號。

## 開始前

- 將 Zeabur Identity 安裝在 `zeabur-identity` Namespace，並使用叢集管理員的 kubeconfig 執行 `kubectl`。
- 準備實際可用的公開網域。Google 只接受公開網域上的重新導向 URI，詳見 [Google 的 URI 驗證規則](https://developers.google.com/identity/protocols/oauth2/web-server#uri-validation)。[在 k3s 上安裝並登入](../get-started/quickstart.mdx)使用的本機名稱 `identity.example.test` 不適用。
- 確認瀏覽器能用該網域連到 Zeabur Identity，並信任它的 TLS 憑證。
- 確認 Zeabur Identity 的 Pod 能用 HTTPS 對外連到 `oauth2.googleapis.com` 和 `www.googleapis.com`。

以下範例使用 `https://identity.example.com`，請將各處範例替換成安裝時設定的 Issuer：

```sh
export ZEABUR_IDENTITY_ISSUER=https://identity.example.com
```

Issuer 在安裝時就已固定。Zeabur Identity 的 Deployment、TLS 憑證和 kube-apiserver 設定必須使用相同名稱。事後修改 shell 裡的 `ZEABUR_IDENTITY_ISSUER`，不會改變既有安裝的 Issuer。

Google 帳號必須先連結到 Zeabur Identity 使用者，才能登入。Zeabur Identity 不會在首次登入時建立使用者，也不會依電子郵件地址、姓名或 Workspace 網域配對帳號。群組和顯示名稱都取自 `User`。

## 設定 Google 登入

<Steps>

<Step>

### 註冊 Google OAuth 用戶端

依照 Google 的 [OpenID Connect 設定文件](https://developers.google.com/identity/openid-connect/openid-connect)和[同意畫面設定指南](https://developers.google.com/workspace/guides/configure-oauth-consent)，在 Google Cloud Console 完成以下設定：

1. 選取或建立專案。在 **Google Auth platform → Branding** 設定應用程式名稱、支援電子郵件和聯絡資料。
2. 在 **Audience** 選擇 **Internal**，只允許你的 Google Workspace 組織使用。若要允許任何 Google 帳號使用，則選擇 **External**。不論選哪一種，使用者都必須先連結 Zeabur Identity 帳號。依照 [Google 的發布規則](https://support.google.com/cloud/answer/15549945)，應用程式在測試模式下會有使用限制。只要求 `openid` 的應用程式不受這項限制，Zeabur Identity 就是這種應用程式。
3. 在 **Data Access** 只宣告 `openid` 範圍，不需要 Google API 資料存取權。
4. 在 **Clients → Create Client** 選擇 **Web application**，設定名稱，並在 **Authorized redirect URI** 加入以下 URI。將網域替換成你的 Issuer：

   ```text
   https://identity.example.com/upstream/google/callback
   ```

   URI 必須與 `<issuer>/upstream/google/callback` 完全相同。**Authorized JavaScript origins** 留空。
5. 記下 **Client ID** 和 **client secret**。Zeabur Identity 需要用戶端密鑰本身，不使用 Google 提供下載的 JSON 檔案。

</Step>

<Step>

### 儲存用戶端密鑰

所有登入提供者的用戶端密鑰都放在同一個 Secret `zeabur-identity-upstream`，一個提供者一個鍵。Zeabur Identity 只能讀取這個 Secret，讀不到其他 Secret。執行以下指令，避免密鑰出現在 shell 歷史紀錄和程式清單中：

```sh
read -rs GOOGLE_SECRET     # paste the client secret, then Enter
printf %s "$GOOGLE_SECRET" | kubectl -n zeabur-identity create secret generic zeabur-identity-upstream \
  --from-file=google=/dev/stdin
unset GOOGLE_SECRET
```

如果 `zeabur-identity-upstream` 已存在，例如裡面已儲存[用 GitHub 登入](./github-sign-in.mdx)所需的密鑰，就用密鑰管理工具加入 `google` 鍵，或執行 `kubectl -n zeabur-identity edit secret zeabur-identity-upstream`。Secret 中的值使用 base64 編碼。

</Step>

<Step>

### 建立 Google 提供者

將 `clientId` 換成你的用戶端 ID：

```sh
kubectl apply -f - <<'EOF'
apiVersion: identity.zeabur.com/v1alpha1
kind: UpstreamProvider
metadata:
  name: google                # the ID in the redirect URI
  namespace: zeabur-identity
spec:
  type: Google
  displayName: Google         # shown as "Continue with Google"
  clientId: 1234567890-example.apps.googleusercontent.com
  clientSecretKey: google     # the key in the Secret zeabur-identity-upstream
EOF
```

幾秒內登入頁就會出現 **Continue with Google**，不必重新啟動。下一步要邀請使用者，所以必須啟用邀請功能（`--serve-arg=--invitations`，如[在 k3s 上安裝並登入](../get-started/quickstart.mdx)所示）。

</Step>

<Step>

### 連結 Google 帳號

依使用者目前的狀態，選擇連結方式：

- 已能登入的一般帳號：開啟帳號頁面，用通行密鑰確認身分，再選擇 **Link Google**。帳號頁面的操作見[管理使用者](./manage-users.mdx)。
- 新使用者：依[管理使用者](./manage-users.mdx)的流程發出邀請。
- 還無法登入的既有使用者：用相同的使用者名稱再次發出邀請。如果使用者已有通行密鑰或已連結帳號，邀請時需要加上 `--reset`。這會先刪除既有的通行密鑰和已連結帳號。救援流程見[登出、救援與移除使用者](./offboarding.mdx)。

使用者開啟設定連結後，選擇 **Continue with Google**，再選取要使用的 Google 帳號。

<Callout type="warn">

拿到設定連結的人就能控制該 Zeabur Identity 使用者，務必將連結交給正確的人。每個設定連結只能新增一個通行密鑰或一個帳號。同一個 Google 帳號同時只能連結到一位使用者。

</Callout>

管理員帳號不能連結 Google 帳號。即使 Google 帳號已啟用雙因素驗證，管理員仍只能用通行密鑰登入，詳見[管理員帳號與工作階段](./admin-sessions.mdx)。

</Step>

</Steps>

## 確認結果

如果你使用[在 k3s 上安裝並登入](../get-started/quickstart.mdx)的 `kubectl` 設定，先清除快取中的工作階段，讓 kubelogin 再次開啟瀏覽器：

```sh
rm -rf ~/.kube/cache/oidc-login
kubectl auth whoami          # choose "Continue with Google"
```

在登入頁選擇 **Continue with Google**，用已連結的一般帳號登入，再檢視 `kubectl auth whoami` 顯示的身分。不要使用快速入門中的 `admin` 等管理員帳號，這些帳號不能用 Google 登入。

### 移除使用者的存取權

已連結的 Google 帳號與通行密鑰一樣，都是 `Credential`。依[管理使用者](./manage-users.mdx)的流程移除該認證資訊，就能阻止使用者再次用該 Google 帳號登入。

若要結束現有工作階段，還需要將使用者登出。若要撤銷所有存取權，則停用或移除使用者，詳見[登出、救援與移除使用者](./offboarding.mdx)。

### 更換用戶端密鑰

更新 `zeabur-identity-upstream` 中的 `google` 鍵。Zeabur Identity 每次登入時都會讀取 Secret，不必重新啟動。

### 關閉 Google 登入

執行 `kubectl -n zeabur-identity delete upstreamprovider google` 刪除提供者。如果不再需要該 OAuth 用戶端，也到 Google Cloud Console 刪除這個用戶端。

關閉 Google 登入不會移除已連結的帳號，也不會結束現有工作階段。需要撤銷存取權時，依上方流程移除認證資訊並將使用者登出。

## 遇到問題

| 畫面或結果 | 接著處理 |
| --- | --- |
| `redirect_uri_mismatch` | 檢查用戶端 ID 和授權的重新導向 URI。通訊協定、主機名稱及 `/upstream/google/callback` 都必須完全相符。`identity.example.test` 這類本機名稱不符合 Google 的網域規則。 |
| `org_internal` 或 Google 存取政策錯誤 | 確認應用程式的 **Audience** 設定是否允許這個帳號登入，也確認帳號所屬組織的政策是否允許存取，詳見 [Google 的對象規則](https://support.google.com/cloud/answer/15549945)。 |
| **This account is not linked to any user here** | 用邀請將選取的 Google 帳號連結到使用者。Zeabur Identity 不依電子郵件地址或姓名配對帳號。 |
| **Use a passkey for this account** | 該 Google 帳號對應到管理員帳號。管理員只能使用通行密鑰登入。 |
| 登入頁沒有 Google 按鈕 | 執行 `kubectl -n zeabur-identity get upstreamproviders`，檢查 `google` 提供者是否存在。 |
| 從 Google 返回後登入失敗 | 執行 `kubectl -n zeabur-identity logs deploy/zeabur-identity`。`client secret unavailable` 表示 Secret `zeabur-identity-upstream` 或其中的 `google` 鍵不存在。否則請檢查 Pod 能否用 HTTPS 連到權杖和簽署金鑰主機：`oauth2.googleapis.com` 與 `www.googleapis.com`。 |
