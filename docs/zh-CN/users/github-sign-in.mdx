在 Zeabur Identity 启用 GitHub 登录，并将 GitHub 账号关联到普通账号后，用户就能在登录页面选择 **Continue with GitHub**，用 GitHub 账号登录。

![登录页面，有通行密钥按钮和 Continue with GitHub](../../images/sign-in-light.avif)

你决定哪些人能登录。未关联的 GitHub 账号无法登录，也不会创建用户。GitHub 组织和团队不影响访问权限，用户组仍由 `User` 决定。Zeabur Identity 记录 GitHub 的数字账号 ID，避免登录名或电子邮箱转给其他人后影响账号识别。

## 开始前

- 完成[在 k3s 上安装并登录](../get-started/quickstart.mdx)。
- 在服务器的 `nix develop` 环境中执行安装命令，并将下方 Issuer 换成你的网址。
- 确认集群允许 Zeabur Identity 的 Pod 通过 HTTPS 连接到外部的 `github.com` 和 `api.github.com`。
- 准备要关联的普通账号。[管理员账号](./admin-sessions.mdx)只能用通行密钥登录，不能关联 GitHub 账号。

```sh
export ZEABUR_IDENTITY_ISSUER=https://identity.example.test
```

## 启用 GitHub 登录

<Steps>

<Step>

### 注册 GitHub OAuth 应用

在 GitHub 打开 **Settings → Developer settings → OAuth Apps → New OAuth App**。你也可以在组织设置中注册，避免应用依赖个人账号。

| 字段 | 配置值 |
|---|---|
| **Application name** | 例如 `Zeabur Identity (zeabur-identity-k3s)`，用户会在 GitHub 的授权页面看到这个名称 |
| **Homepage URL** | `https://identity.example.test` |
| **Authorization callback URL** | `https://identity.example.test/upstream/github/callback` |
| **Enable Device Flow** | 关闭 |

将网址换成你的 Issuer。回调网址只负责重定向浏览器。

注册完成后，记下 **Client ID**，并生成 **client secret**。

</Step>

<Step>

### 存储客户端密钥

Zeabur Identity 从 Kubernetes Secret 中的文件读取密钥，挂载路径为 `/etc/zeabur-identity`。

执行以下命令，避免密钥出现在 Shell 历史记录和进程列表中：

```sh
read -rs GITHUB_SECRET     # paste the client secret, then Enter
printf %s "$GITHUB_SECRET" | kubectl -n zeabur-identity create secret generic zeabur-identity-config \
  --from-file=github-client-secret=/dev/stdin
unset GITHUB_SECRET
```

如果 `zeabur-identity-config` 已存在，例如已存放 [Google 登录](./google-sign-in.mdx)的密钥，改用以下命令添加键，保留其他键：

```sh
kubectl -n zeabur-identity edit secret zeabur-identity-config
```

</Step>

<Step>

### 启用 GitHub 登录提供方

使用 Secret 和 Client ID 重新生成部署配置。

`zeabur-identityctl manifests` 不会记住之前的选项。执行时要保留安装时使用的镜像、Namespace 和其他 `--serve-arg`，再加上 GitHub 选项。

以下命令沿用[在 k3s 上安装并登录](../get-started/quickstart.mdx)的配置，包含下一步邀请用户所需的 `--invitations`。将 `GITHUB_CLIENT_ID` 换成刚才获取的 **Client ID**；这个值不属于密钥。

```sh
GITHUB_CLIENT_ID=Ov23li...   # from step 1; not a secret
ZEABUR_IDENTITY_IMAGE=$(kubectl -n zeabur-identity get deployment zeabur-identity -o jsonpath='{.spec.template.spec.containers[0].image}')
zeabur-identityctl manifests --image "$ZEABUR_IDENTITY_IMAGE" \
  --config-secret zeabur-identity-config \
  --serve-arg=--invitations \
  --serve-arg=--github-client-id=$GITHUB_CLIENT_ID \
  --serve-arg=--github-client-secret-file=/etc/zeabur-identity/github-client-secret \
  | kubectl apply --server-side -f -
kubectl -n zeabur-identity rollout status deploy/zeabur-identity
```

部署完成后，登录页面会显示 **Continue with GitHub**。

</Step>

<Step>

### 将 GitHub 账号关联到用户

根据用户当前的状态选择关联方式：

- 已能登录的用户：打开账号页面，用通行密钥确认身份，再选择 **Link GitHub**。管理员账号不能关联。
- 新用户：按照[管理用户](./manage-users.mdx)中的步骤创建邀请。
- 已有账号但还无法登录的用户：用相同用户名再次创建邀请。如果账号已有通行密钥或已关联的账号，邀请需要加上 `--reset`。账号恢复操作见[退出登录、恢复与移除用户](./offboarding.mdx)。

用户打开邀请链接后，选择 **Continue with GitHub**，不创建通行密钥，再登录要关联的 GitHub 账号。每个链接只能添加一把通行密钥或一个账号。

<Callout type="warn">

`--reset` 会先删除用户现有的通行密钥和已关联的账号。

</Callout>

#### 进阶：不使用链接，直接创建 Credential

如果你知道用户的 GitHub 登录名，也可以直接创建 `Credential`。对象必须满足以下条件：

- `metadata.name` 根据 GitHub 的数字账号 ID 生成，Zeabur Identity 会按名称查找账号。
- 用户标签让[管理用户](./manage-users.mdx)中的命令能找到这条凭据。
- `ownerReferences` 指向登录身份所属的 `User`，并填入该 `User` 的 UID。删除用户时，Kubernetes 也会删除这条凭据。

缺少 `ownerReferences`，或 UID 指向其他 `User`，都会导致 GitHub 账号无法登录。

将 `LOGIN` 换成 GitHub 登录名，将 `USER_NAME` 换成现有的 `User` 名称：

```sh
LOGIN=octocat
USER_NAME=alice                                   # an existing User object
USER_UID=$(kubectl -n zeabur-identity get users.identity.zeabur.com "$USER_NAME" -o jsonpath='{.metadata.uid}')
GH_ID=$(curl -fsS https://api.github.com/users/$LOGIN | jq -r .id)
NAME=c-$(printf 'zeabur-identity/external/v1/https://github.com\0%s' "$GH_ID" | sha256sum | cut -d' ' -f1)
kubectl apply -f - <<EOF
apiVersion: identity.zeabur.com/v1alpha1
kind: Credential
metadata:
  name: $NAME
  namespace: zeabur-identity
  labels: {identity.zeabur.com/user: "$USER_NAME"}
  ownerReferences:
    - {apiVersion: identity.zeabur.com/v1alpha1, kind: User, name: $USER_NAME, uid: $USER_UID}
spec:
  type: GitHub
  user: $USER_NAME
  external: {issuer: "https://github.com", subject: "$GH_ID"}
EOF
```

<Callout type="warn">

执行 `kubectl apply` 前，先确认 `$GH_ID`。填错 ID 会关联到其他人的 GitHub 账号。

</Callout>

</Step>

</Steps>

## 确认结果

在你的电脑上清除缓存的会话，让 kubelogin 再次打开浏览器。执行以下命令后，选择 **Continue with GitHub**：

```sh
rm -rf ~/.kube/cache/oidc-login
export KUBECONFIG=~/.kube/zeabur-identity-k3s.yaml
kubectl auth whoami          # choose "Continue with GitHub"; the user is zeabur:<username>
```

确认 `kubectl auth whoami` 显示的用户为 `zeabur:<username>`。

你也可以通过输出中的 `identity.zeabur.com/amr` 区分登录方式：

- 使用通行密钥登录时，列出 `swk` 和 `mfa`。
- 使用 GitHub 登录时，内容为空。

使用普通账号验证。快速入门创建的 `admin` 等管理员账号不接受 GitHub 登录。

## 移除 GitHub 登录权限

已关联的 GitHub 账号和通行密钥一样，都是 `Credential`：

- 移除已关联的账号，阻止该账号发起新的登录。操作见[管理用户](./manage-users.mdx)。
- 让用户退出登录，结束已创建的会话。操作见[退出登录、恢复与移除用户](./offboarding.mdx)。
- 停用或移除用户，撤销所有访问权限。操作见[退出登录、恢复与移除用户](./offboarding.mdx)。

要关闭 GitHub 登录，重新生成部署配置时移除两个 `--github-*` 选项，保留其他选项，再到 GitHub 删除 OAuth 应用。已关联的账号和现有会话仍会保留，需要按上面的方式移除。

## 遇到问题

| 界面或结果 | 处理方法 |
|---|---|
| GitHub 显示重定向 URI 不属于此应用 | 确认 OAuth 应用的回调网址与 `<issuer>/upstream/github/callback` 完全相同。 |
| **This account is not linked to any user here** | GitHub 账号没有对应的 `Credential`。按照关联账号的步骤处理。手动创建的凭据如果名称或 ID 错误，也会出现相同提示。 |
| **Use a passkey for this account** | GitHub 账号关联到了管理员账号。管理员账号只能用通行密钥登录。 |
| **This provider is not enabled** | Deployment 缺少 `--github-client-id`。执行 `kubectl -n zeabur-identity get deploy zeabur-identity -o jsonpath='{.spec.template.spec.containers[0].args}'` 检查参数。 |
| Pod 无法读取 `/etc/zeabur-identity/...` | 确认 `--config-secret zeabur-identity-config` 已挂载 Secret，Secret 包含 `github-client-secret`，且 `--github-client-secret-file` 指向 `/etc/zeabur-identity/github-client-secret`。如果你自定义了 Pod 的安全配置或挂载，保留生成配置中的 `fsGroup` 和读取权限。 |
| GitHub 重定向回来后登录失败 | Pod 无法连接到 `github.com` 或 `api.github.com`。检查对外连接配置，包括代理服务器、防火墙和 NetworkPolicy，并执行 `kubectl -n zeabur-identity logs deploy/zeabur-identity` 查看日志。 |
