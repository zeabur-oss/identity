配置 Google OAuth 客户端，再将 Google 账号关联到 Zeabur Identity 用户，用户就能在登录页选择 **Continue with Google**。管理员账号只能用通行密钥登录，不能关联 Google 账号。

## 开始前

- 将 Zeabur Identity 安装在 `zeabur-identity` Namespace，并使用集群管理员的 kubeconfig 执行 `kubectl`。
- 准备真实的公共域名。Google 只接受公共域名上的重定向 URI，详见 [Google 的 URI 验证规则](https://developers.google.com/identity/protocols/oauth2/web-server#uri-validation)。[在 k3s 上安装并登录](../get-started/quickstart.mdx)使用的本地名称 `identity.example.test` 不适用。
- 确认浏览器能通过该域名连接 Zeabur Identity，并信任其 TLS 证书。
- 确认 Zeabur Identity 的 Pod 能通过 HTTPS 向外连接 `oauth2.googleapis.com` 和 `www.googleapis.com`。

以下示例使用 `https://identity.example.com`，请将各处示例替换成安装时配置的 Issuer：

```sh
export ZEABUR_IDENTITY_ISSUER=https://identity.example.com
```

Issuer 在安装时就已固定。Zeabur Identity 的 Deployment、TLS 证书和 kube-apiserver 配置必须使用相同名称。安装后修改 shell 里的 `ZEABUR_IDENTITY_ISSUER` 不会更改现有安装的 Issuer。

Google 账号必须先关联到 Zeabur Identity 用户，才能登录；也可以按下文说明，让 Zeabur Identity 为你的 Workspace 域名创建用户。Zeabur Identity 不会根据电子邮件地址或姓名匹配账号。用户的组和显示名称都取自 `User`。

## 配置 Google 登录

<Steps>

<Step>

### 注册 Google OAuth 客户端

按照 Google 的 [OpenID Connect 配置文档](https://developers.google.com/identity/openid-connect/openid-connect)和[同意屏幕配置指南](https://developers.google.com/workspace/guides/configure-oauth-consent)，在 Google Cloud Console 完成以下配置：

1. 选择或创建项目。在 **Google Auth platform → Branding** 配置应用名称、支持电子邮件地址和联系信息。
2. 在 **Audience** 选择 **Internal**，仅允许你的 Google Workspace 组织使用；或选择 **External**，允许任何 Google 账号使用。[Google 的发布规则](https://support.google.com/cloud/answer/15549945)会限制测试模式中的应用，但只请求 `openid` 的应用不受此限制，Zeabur Identity 就属于这种情况。
3. 在 **Data Access** 只声明 `openid` 范围，不需要 Google API 数据访问权限。
4. 在 **Clients → Create Client** 选择 **Web application**，配置名称，并在 **Authorized redirect URI** 添加以下 URI。将域名替换成你的 Issuer：

   ```text
   https://identity.example.com/upstream/google/callback
   ```

   URI 必须与 `<issuer>/upstream/google/callback` 完全相同。**Authorized JavaScript origins** 留空。
5. 记下 **Client ID** 和 **client secret**。Zeabur Identity 需要客户端密钥本身，不使用 Google 提供下载的 JSON 文件。

</Step>

<Step>

### 存储客户端密钥

所有登录提供方的客户端密钥都保存在同一个 Secret `zeabur-identity-upstream` 中，每个提供方一个键。Zeabur Identity 只能读取这个 Secret，读不到其他 Secret。执行以下命令，避免密钥出现在 shell 历史记录和进程列表中：

```sh
read -rs GOOGLE_SECRET     # paste the client secret, then Enter
printf %s "$GOOGLE_SECRET" | kubectl -n zeabur-identity create secret generic zeabur-identity-upstream \
  --from-file=google=/dev/stdin
unset GOOGLE_SECRET
```

如果 `zeabur-identity-upstream` 已存在，例如已存储[用 GitHub 登录](./github-sign-in.mdx)所需的密钥，就用密钥管理工具添加 `google` 键，或执行 `kubectl -n zeabur-identity edit secret zeabur-identity-upstream`。Secret 中的值使用 base64 编码。

</Step>

<Step>

### 创建 Google 提供方

将 `clientId` 换成你的客户端 ID：

```sh
kubectl apply -f - <<'EOF'
apiVersion: identity.zeabur.com/v1alpha1
kind: UpstreamProvider
metadata:
  name: google                # the ID in the redirect URI
  namespace: zeabur-identity
spec:
  type: Google
  displayName: Google         # shown as "Continue with Google"
  clientId: 1234567890-example.apps.googleusercontent.com
  clientSecretKey: google     # the key in the Secret zeabur-identity-upstream
EOF
```

几秒内登录页就会出现 **Continue with Google**，无需重启。下一步要邀请用户，所以必须启用邀请功能（`--serve-arg=--invitations`，如[在 k3s 上安装并登录](../get-started/quickstart.mdx)所示）。

</Step>

<Step>

### 关联 Google 账号

根据用户当前的状态，选择关联方式：

- 已能登录的普通账号：打开账号页面，用通行密钥验证身份，再选择 **Link Google**。账号页面的操作见[管理用户](./manage-users.mdx)。
- 新用户：按[管理用户](./manage-users.mdx)的流程发送邀请。
- 尚不能登录的现有用户：使用相同用户名再次发送邀请。如果用户已有通行密钥或已关联账号，邀请时需要 `--reset`，这会先删除现有的通行密钥和已关联账号。救援流程见[退出登录、救援与移除用户](./offboarding.mdx)。

用户打开设置链接后，选择 **Continue with Google**，再选择要使用的 Google 账号。

<Callout type="warn">

拿到设置链接的人就能控制该 Zeabur Identity 用户，务必将链接交给正确的人。每个设置链接只能添加一个通行密钥或一个账号。同一个 Google 账号同时只能关联到一位用户。

</Callout>

管理员账号不能关联 Google 账号。即使 Google 账号已启用双因素验证，管理员仍只能用通行密钥登录，详见[管理员账号与会话](./admin-sessions.mdx)。

</Step>

</Steps>

## 确认结果

如果你使用[在 k3s 上安装并登录](../get-started/quickstart.mdx)的 `kubectl` 配置，先清除缓存的会话，让 kubelogin 再次打开浏览器：

```sh
rm -rf ~/.kube/cache/oidc-login
kubectl auth whoami          # choose "Continue with Google"
```

在登录页选择 **Continue with Google**，使用已关联的普通账号登录，并查看 `kubectl auth whoami` 显示的身份。不要使用快速入门中的 `admin` 等管理员账号，这些账号不接受 Google 登录。

### 移除用户的访问权限

已关联的 Google 账号与通行密钥一样，都是 `Credential`。按[管理用户](./manage-users.mdx)的流程移除该凭据，就能阻止用户再次用该 Google 账号登录。

如果要结束现有会话，还需要让用户退出登录。如果要撤销所有访问权限，则停用或移除用户，详见[退出登录、救援与移除用户](./offboarding.mdx)。

### 更换客户端密钥

更新 `zeabur-identity-upstream` 中的 `google` 键。Zeabur Identity 每次登录时都会读取该 Secret，无需重启。

### 关闭 Google 登录

执行 `kubectl -n zeabur-identity delete upstreamprovider google` 删除提供方。如果不再需要该 OAuth 客户端，也在 Google Cloud Console 删除这个客户端。

关闭 Google 登录不会移除已关联的账号，也不会结束现有会话。需要撤销访问权限时，按上方流程移除凭据并让用户退出登录。

## 为 Workspace 域名创建用户

不想逐个关联账号的话，可以让 Zeabur Identity 在你的 Google Workspace 域名成员首次登录时，自动创建普通账号的 `User`。在 `google` 提供方中添加 `provisioning`，`values` 填你的域名：

```yaml
spec:
  # type, displayName, clientId and clientSecretKey as above
  provisioning:
    claim: hd                     # the account's Workspace domain
    values: [example.com]
```

此时 Zeabur Identity 会向 Google 请求 `openid profile email`，所以也要在 **Data Access** 中声明 `email` 和 `profile`。用户名取电子邮件地址 `@` 之前的部分。创建用户的规则与其他提供方相同，启用前请先阅读[让用户用组织的身份提供方登录](./oidc-sign-in.mdx)中的“首次登录时创建用户”。

## 遇到问题

| 界面或结果 | 后续处理 |
| --- | --- |
| `redirect_uri_mismatch` | 检查客户端 ID 和授权的重定向 URI。协议、主机名及 `/upstream/google/callback` 都必须完全匹配。`identity.example.test` 这类本地名称不符合 Google 的域名规则。 |
| `org_internal` 或 Google 访问政策错误 | 检查应用的 **Audience** 和账号所属组织的政策，详见 [Google 的受众规则](https://support.google.com/cloud/answer/15549945)。 |
| **This account is not linked to any user here** | 使用邀请将选定的 Google 账号关联到用户。Zeabur Identity 不按电子邮件地址或姓名匹配账号。 |
| **Use a passkey for this account** | 该 Google 账号对应管理员账号。管理员只能使用通行密钥登录。 |
| 登录页没有 Google 按钮 | 执行 `kubectl -n zeabur-identity get upstreamproviders`，检查 `google` 提供方是否存在。 |
| 从 Google 返回后登录失败 | 执行 `kubectl -n zeabur-identity logs deploy/zeabur-identity`。`client secret unavailable` 表示 Secret `zeabur-identity-upstream` 或其中的 `google` 键不存在。否则请检查 Pod 能否用 HTTPS 连接到令牌和签名密钥主机：`oauth2.googleapis.com` 和 `www.googleapis.com`。 |
