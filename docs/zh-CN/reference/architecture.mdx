Zeabur Identity 是以通行密钥为主要登录方式的 OpenID Connect Issuer，在自管 Kubernetes 集群中运行。kube-apiserver 使用 [Structured Authentication Configuration][kep-3331]，自行验证 Zeabur Identity 签发的令牌。你可以用通行密钥登录，无需持有无法撤销的长期有效的管理员 kubeconfig。其他 OpenID Connect 客户端，例如 Argo CD、Grafana 和 Headlamp，也能使用同一个 Issuer。

k3s 和 RKE2 使用相同配置。CI 测试涵盖 k3s。

## 安全特性

- **不使用密码。** 通行密钥是主要凭证，使用 WebAuthn，且必须完成用户验证。日常访问也可以改用关联的 GitHub 或 Google 账号登录。
- **管理员权限只授予管理员账号。** 只有 `accountType: Admin` 的 `User` 会获得 `zeabur:admins` 组，该组绑定 `cluster-admin`。管理员账号只能用通行密钥登录，令牌默认有效期为五分钟，会话也可能因空闲而提前结束。如果安装配置启用 AAL3，管理员账号还必须使用绑定设备的通行密钥。普通账号只能获得所属组绑定的权限。所有会话都会在登录 12 小时后结束。
- **令牌有效期短。** 令牌绑定目标受众（audience），签名密钥会定期轮换。
- **用户自行管理登录方式。** 添加或移除通行密钥、关联或取消关联 GitHub 或 Google 账号，都需要重新使用通行密钥完成验证。用户无法移除最后一把通行密钥，也无法取消关联最后一种登录方式。
- **状态存储在 Kubernetes 中。** 自定义资源存储用户、凭证、客户端、会话与邀请，无需数据库。撤销访问权限与删除数据的顺序，见[退出登录、救援与移除用户](../users/offboarding.mdx)。

[规范符合度](./conformance.mdx)列出 Zeabur Identity 实现的各项规范要求，以及对应的代码和验证测试。

## 组件如何协作

```text
browser ──passkey──▶ zeabur-identity (in the cluster) ──tokens──▶ kubectl / OIDC clients
                        │  ▲                                     │
                 custom resources                       bearer token
                        ▼  │                                     ▼
                  kube-apiserver ◀──discovery + keys (internal TLS)── verifies tokens itself
```

一次 `kubectl` 请求的流程如下。

<Steps>

<Step>

### 打开登录页面

kubelogin 打开浏览器，前往 Zeabur Identity 的登录页面。

</Step>

<Step>

### 使用通行密钥登录

用户使用通行密钥登录。kubelogin 获取短期有效的访问令牌和刷新令牌，Zeabur Identity 则通过 `Grant` 对象记录会话。

</Step>

<Step>

### 发送令牌

`kubectl` 将令牌发送给 kube-apiserver。

</Step>

<Step>

### 验证令牌

kube-apiserver 使用 Zeabur Identity 公开的密钥，验证令牌签名。密钥通过内部 TLS 连接获取，Zeabur Identity 不参与这次请求本身。

</Step>

<Step>

### 刷新过期令牌

令牌到期后，kubelogin 使用刷新令牌获取新令牌，无需打开浏览器。

</Step>

</Steps>

管理工具 `zeabur-identityctl` 在管理员的电脑上运行，使用管理员自己的 kubeconfig，负责输出安装清单、生成适用于该 Kubernetes 发行版的 kube-apiserver `AuthenticationConfiguration`，以及签发供用户注册通行密钥的一次性链接。

## Crate 分工

代码分成多个小型 crate，全部放在同一层的 `crates/` 目录：

- **依赖关系只向下，不形成循环。** 参考 [Kladov][matklad-workspaces]，以及下方参考文献中的 Lakos 和 Martin。
- **每个 crate 用窄接口封装一项设计决策。** 参考 [Parnas][parnas]。
- **存储层由一组 trait 定义。** 内存与 Kubernetes 各有实现，所以大多数测试无需集群。这里采用 ports and adapters 架构，参考 [Cockburn][cockburn]。
- **服务器与管理 CLI 使用不同的可执行文件。** Kanidm（`kanidmd`／`kanidm`）、etcd（`etcd`／`etcdctl`）和 cert-manager（`cmctl`）也采用这种分工。只有管理员需要运行的代码，不会放进服务器镜像。

每个 crate 的 README 同时是该 crate 的 crate 级文档，可用 `cargo doc --open` 打开。

| Crate | 内容 | 依赖 |
|---|---|---|
| [`zeabur-identity-core`](https://github.com/zeabur-oss/identity/tree/main/crates/zeabur-identity-core) | 时间、加密辅助工具、已验证的配置值、协议名称 | — |
| [`zeabur-identity-keys`](https://github.com/zeabur-oss/identity/tree/main/crates/zeabur-identity-keys) | 签名密钥、JWK 发布、JWS 签名与验证、密钥轮换 | core |
| [`zeabur-identity-store`](https://github.com/zeabur-oss/identity/tree/main/crates/zeabur-identity-store) | 存储端口（trait、记录）与内存适配器 | core, keys |
| [`zeabur-identity-tls`](https://github.com/zeabur-oss/identity/tree/main/crates/zeabur-identity-tls) | 信任根、证书签发、可重新加载的 TLS 监听器 | core |
| [`zeabur-identity-ui`](https://github.com/zeabur-oss/identity/tree/main/crates/zeabur-identity-ui) | 服务器渲染的页面、内嵌资源、翻译、安全响应头 | core |
| [`zeabur-identity-oauth`](https://github.com/zeabur-oss/identity/tree/main/crates/zeabur-identity-oauth) | OAuth 2.0 / OpenID Connect 授权服务器 | core, keys, store, ui |
| [`zeabur-identity-signin`](https://github.com/zeabur-oss/identity/tree/main/crates/zeabur-identity-signin) | 通行密钥注册与登录、上游提供方、页面路由 | core, keys, store, oauth, ui |
| [`zeabur-identity-k8s`](https://github.com/zeabur-oss/identity/tree/main/crates/zeabur-identity-k8s) | 自定义资源、Kubernetes 适配器、GC、清单、kube-apiserver 配置 | core, keys, store, tls |
| [`zeabur-identity`](https://github.com/zeabur-oss/identity/tree/main/crates/zeabur-identity) | **可执行文件**：集群内的服务器 | 以上所有 crate |
| [`zeabur-identityctl`](https://github.com/zeabur-oss/identity/tree/main/crates/zeabur-identityctl) | **可执行文件**：管理员 CLI | core, k8s |
| [`zeabur-identity-test-support`](https://github.com/zeabur-oss/identity/tree/main/crates/zeabur-identity-test-support), [`zeabur-identity-e2e`](https://github.com/zeabur-oss/identity/tree/main/crates/zeabur-identity-e2e) | 测试辅助工具；集群上的端到端测试 | — |

登录页面的 TypeScript 与 Tailwind 源码放在 [`ui/`](https://github.com/zeabur-oss/identity/tree/main/ui)，并以包的形式使用 Zeabur 设计系统。构建产物与设计系统的样式类都会提交到 `crates/zeabur-identity-ui`，并嵌入可执行文件。样式类以 askama 宏的形式存储在 `templates/ds.html` 中。
