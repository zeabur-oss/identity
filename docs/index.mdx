Zeabur Identity is the sign-in for your cluster. Each person signs in with their own account, using a passkey, GitHub, Google, your company's OpenID provider or a password, and gets a token that lasts a few minutes. Admins need two factors by default. Nobody shares an admin password or an admin kubeconfig.

## I use Zeabur

Zeabur's sign-in page is Zeabur Identity, so a cluster that runs Zeabur already has it. You manage people in Zeabur:

- To invite people and choose which projects they can open, use **Members**. See [Invite members and assign project permissions](https://oss.zeabur.com/docs/zeabur/cluster/members/).
- To set up Zeabur on a cluster, one `helm install` installs Zeabur and Zeabur Identity together. See [Install Zeabur in an existing cluster](https://oss.zeabur.com/docs/zeabur/install/existing-cluster/).

To move from zeabur.com to your own server, or for anything else about Zeabur, see the [Zeabur documentation](https://oss.zeabur.com/docs/zeabur/).

## I use Zeabur Identity on its own

Zeabur Identity replaces the admin kubeconfig that never expires. `kubectl` opens a browser, you sign in, and kube-apiserver checks the short-lived token on every request. Users, credentials, and clients are Kubernetes objects in the `zeabur-identity` Namespace, with no database.
